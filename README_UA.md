# Автоматизована система локалізації мін та відстеження телеметрії (Automated Mine Localization & Telemetry Tracking System)

Комплексна телеметрична система для гуманітарного розмінування, розроблена для прискорення виявлення та картографування мін за допомогою біодетекторів (навчених HeroRATs) у поєднанні з низькоспоживаними сенсорами периферійних обчислень (edge sensing) та GIS-картографуванням у реальному часі.

---

## 1. Мета проєкту (Project Objective)

Міни та вибухонебезпечні предмети (ВНП) залишаються критичною гуманітарною загрозою в зонах воєнних дій, блокуючи безпечний доступ до родючих сільськогосподарських земель і критичної інфраструктури. Традиційне ручне розмінування є небезпечним, трудомістким і повільним процесом.

Мета цього проєкту — **прискорити процес гуманітарного розмінування** шляхом автоматизації реєстрації виявлень та польової телеметрії. Створена на основі досвіду таких організацій, як [APOPO](https://apopo.org/), та їхнього використання тварин для виявлення за запахом (див. [HeroRATs in Action](https://youtu.be/UE94Sxp6mY8?is=pz8ypWkEKs3injI2)), ця система будує цифровий міст між пошуковою роботою в полі та координатами на карті, мінімізуючи перебування операторів у потенційно небезпечних зонах.

---

## 2. Потік виявлення та принцип роботи (Localization Flow & Working Mechanism)

Система працює за двома паралельними пайплайнами:
1. **Безперервне відстеження в реальному часі (Continuous Real-Time Tracking):** щосекунди транслює поточні координати для моніторингу траєкторії руху пошукової тварини в реальному часі.
2. **Сповіщення про виявлення за подією (Event-Driven Localization Alert):** миттєво спрацьовує, коли відчувається запах вибухівки та натискається touch sensor.

### Детальний опис пайплайнів

#### 1. Continuous Position Tracking (1 Hz)
* **Періодичний запит (Periodic Polling):** Щосекунди ESP32 зчитує поточну широту, довготу та якість GPS fix (обробляються лише GPS-дані з допустимим рівнем достовірності та якості).
* **Стрімінг на базову станцію (Stream to Base Station):** Координати пакуються в періодичний heartbeat UDP-датаграм та передаються через Wi-Fi у застосунок `/mine_tracker`, що працює на Raspberry Pi.
* **Пересилання через MAVLink (MAVLink Forwarding):** Raspberry Pi транслює безперервні координати у повідомлення MAVLink глобальної позиції (`GLOBAL_POSITION_INT` / `HEARTBEAT`), які надсилаються на UDP-порт `14550`.

#### 2. Event-Driven Localization Alert
1. **Ідентифікація цілі (Target Identification):** Відчувши випари вибухівки, HeroRAT шкрябає або торкається закріпленого на шлейці touch sensor.
2. **Миттєвий звуковий сигнал-винагорода (Instant Acoustic Reward Cue):** ESP32 протягом мілісекунд генерує чіткий клацаючий сигнал на piezo buzzer. Це слугує умовним підкріпленням, сигналізуючи тварині, що на лінії старту/межі її чекає смачна винагорода.
3. **Фіксація телеметрії небезпеки (Hazard Telemetry Capture):** Одночасно ESP32 фіксує координати та надсилає пакет сповіщення (alert payload) до `/mine_tracker`.
4. **Просторова кореляція (Spatial Correlation):** Raspberry Pi перевіряє пороговий радіус (наприклад, `15 m` або значення за замовчуванням `30 m`). Точки в межах радіуса кластера оновлюють центроїд існуючого кластера; координати за його межами формують новий підозрілий кластер.
5. **Позначення на карті (Map Pinning):** QGroundControl миттєво відображає помітний маркер небезпеки (waypoint) на супутниковій карті для саперної групи.

## 3. Локалізація та радіус кластеризації (Localization & Clustering Radius)

> **Примітка щодо точності GPS:**  
> У поточному прототипі використовується стандартний комерційний модуль GPS, який має позиційний дрейф та похибку вимірювань ($\pm 5$–$15$ метрів) у динамічних польових умовах.  
> 
> Через це апаратне обмеження програмне забезпечення для відстеження (`mine_tracker`) використовує настроюваний радіус кластеризації (наприклад, `--radius 30`). Просторові спрацьовування в межах цього порогу об'єднуються як такі, що належать до одного кластера потенційної цілі, замість створення дублікатів маркерів небезпеки.  
> 
> Кожен цільовий кластер підтримує динамічний рівень достовірності (confidence score) на основі частоти та часу надходження сигналів виявлення:  
> 
> * **Просторове об'єднання (Spatial Consolidation):** Повторні спрацьовування, зафіксовані в межах заданого радіуса кластера, підтверджують імовірність наявності реальної цілі, а не випадкового артефакту сенсора.  
> * **Часове зважування / швидкі спрацьовування (Temporal Weighting / Rapid Triggers):** Якщо кілька сигналів надходять швидко один за одним — менш ніж за 5 секунд, — рівень достовірності кластера отримує додаткове збільшення. Це відповідає поведінці тварини, яка зосереджено шкрябає/натискає датчик безпосередньо над джерелом запаху, і дозволяє уникнути штучного завищення ваги одиночних випадкових шумів.  
> 
> Сповіщення та координати міни надсилаються до QGroundControl, коли рівень достовірності (confidence) досягає або перевищує 80%, що відповідає 3 чітким сигналам у цій зоні.

## 4. Архітектура системи (System Architecture)

Проєкт складається з двох основних підмодулів:

* **[`/mine_detector`](./mine_detector):** Прошивка на C++ / ESP-IDF для мікроконтролера ESP32. Взаємодіє з touch sensor, модулем GPS та buzzer, транслюючи телеметрію через UDP.
* **[`/mine_tracker`](./mine_tracker):** Серверна частина (backend) на C++, що працює на Raspberry Pi. Приймає вхідні сповіщення через UDP, кластеризує події виявлення, надає доступ до HTTP REST API через Crow та транслює маркери у GIS-програми через MAVLink.

## 5. Швидкий старт та інструкція з експлуатації (Quick Start & Operational Walkthrough)

### Крок 1: Запуск `mine_tracker` на Raspberry Pi
Увімкніть живлення Raspberry Pi та запустіть сервіс відстеження (переконайтеся, що активовано hotspot або спільну мережу Wi-Fi):

```bash
cd ~/Documents/mine_tracker/build
./mine_tracker --radius 35
```

### Крок 2: Увімкнення вузла ESP32
Підключіть акумулятор або джерело живлення до шлейки з ESP32. ESP32 автоматично підключиться до мережі Wi-Fi базової станції (Raspberry Pi) і почне опитування даних GPS.

### Крок 3: Підключення QGroundControl
1. Запустіть **QGroundControl** на польовому ноутбуці чи планшеті оператора.
2. Відкрийте **Application Settings** $\rightarrow$ **Comm Links**.
3. Додайте нове з'єднання **UDP Connection** зі стандартним портом (`14550`).
4. Підключіться та перейдіть у режим **Fly Mode**, щоб спостерігати за нанесенням координат виявлення та кластерів цілей на живу супутникову карту.

## 6. План розвитку та майбутні покращення (Roadmap & Future Improvements)

- [ ] **Persistent Storage & State Recovery:** Збереження всіх точок сповіщень, груп кластерів та історії достовірності в постійній базі даних на Raspberry Pi, щоб уникнути втрати телеметрії міток в разі перезапуску сервісу.
- [ ] **Startup State Sync:** Автоматичне завантаження активних просторових кластерів у блок аналізу виявлень під час запуску для запобігання втраті даних після перезавантаження.
- [ ] **Robust Offline & Sensor Fail-safes:** Реалізація обробки помилок та локального кешування (наприклад, flash ring buffer) на ESP32 для збереження міток часу та спрацьовувань сенсорів у разі обриву Wi-Fi, а також резервна логіка для ситуацій із застарілими чи втраченими GPS fix під час активного проходу.
- [ ] **Autonomous Feeder Rover:** Інтеграція автономного мобільного ровера-годувальника, який слідує за твариною для видачі їстівної винагороди безпосередньо в полі.
- [ ] **RTK Precision Upgrade:** Заміна стандартного GPS на RTK для усунення поточного дрейфу позиціювання у $30\text{ m}$ (з урахуванням радіуса дії ровера). Завдяки сантиметровій точності сапери зможуть виходити безпосередньо на точне місце залягання міни замість обстеження широких зон.
